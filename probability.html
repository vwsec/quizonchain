Probabilities of Key Failure

Two phases of failure — ping (5s) and generation (30s) — across 3, 5, or N keys

Phase 1 — Ping 5s timeout

Why a key fails the ping

🚫 Rate limited 429
Daily quota exhausted (14,400 req/day per key). Most common failure — happens when traffic is sustained at >1 req/6s per key
most common
🔑 Auth failure 401
Key was manually rotated, revoked, or leaked. Won't recover until the env var is updated
uncommon
⏱ Timeout
Network congestion, Groq API routing slow, or DNS issue. 5s window catches most transient blips
rare
🌐 Network error
DNS resolution failure, TCP reset, TLS handshake error. Usually Vercel-side networking issue
very rare
💸 Insufficient balance
Account ran out of credits or hit billing limits
very rare
🔴 Server error 500
Groq API internal error on the tiny ping request. Temporary, next retry usually works
very rare
Phase 2 — Generation 30s timeout

Why generation fails on a healthy key

📝 Invalid JSON
Model output is not valid JSON. ~2–5% of responses depending on prompt complexity. The validation pipeline catches this and retries or falls back
~2-5%
🧹 Bad questions
Questions fail quality filter (URL, "404", "page not found") or contamination filter (cross-chain names in wrong answers). ~5-10% have <3 valid
~5-10%
🚫 Rate limited 429
Key passed ping (1 token) but generation (2000+ tokens) exhausted remaining quota. Unlikely but possible when key is near limit
low
⏱ Timeout
30s not enough for generation (large prompt, high model load). Ping confirmed responsiveness so this is rare
rare
🔴 Server error 500
Groq API failed processing the full request. Transient
very rare
