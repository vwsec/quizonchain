📚Load Quiz Questions from Question Pool
Once connected, the app fetches 5 questions from a pre-written question pool (JSON files on the server). Each chain has its own pool with hundreds of questions about that blockchain.
GET /api/generate-quiz Pre-written pools 5 questions 4 options each
Server looks for data/quizzes-{chain}.json (e.g. quizzes-base.json, quizzes-ink.json)
If you're connected with a wallet: questions are served sequentially — each time you play you get the next 5 questions from the pool (tracked via Redis)
If not authenticated: 5 random questions are picked from the pool
Options are shuffled so the correct answer isn't always in the same spot
Server returns: { questions, quizToken, ecosystem, startIndex }
📦 The quizToken is a JWT containing the correct answers — signed by the server, invisible to you
⚠️ If the pool file is missing or has fewer than 5 questions, it falls back to hardcoded fallback questions built into the code

QuizScreen Client-side only Immediate feedback

✅Verify Answers (Server-Side)
Your answers are sent to the server. The server compares them against the secret JWT it made earlier (step 2) and returns your real score. You cannot cheat — the correct answers are server-side only.
POST /api/verify-quiz JWT verification Anti-cheat
Client sends: { quizToken, answers }
Server decodes the JWT, pulls stored correct answers, compares with yours
Server also checks Redis to stop replay attacks (same quiz submitted twice)
Returns: { score: 3 } — your real score

ResultsScreen Count-up animation NFT progress

Click "Submit Score On-chain" to proceed
A confirmation modal opens showing estimated gas — click Confirm

6
✍️Server Signs Your Score
Before sending a blockchain transaction, the app asks the server to digitally sign your score. The server uses a private key (the "trusted signer") to create a signature that proves: "I, the official QuizOnChain server, confirm this player got this score."
POST /api/sign-score ECDSA EIP-191 Rate limited
Client sends: { playerAddress, score, total, nonce, chainId, contractAddress, quizToken, answers }
Anti-cheat: Server recalculates the score from the JWT — if it doesn't match what you claimed, REJECTED
If score is valid, the server encodes: keccak256(abi.encode(player, score, total, nonce, chainId, contract))
Server signs it with QUIZ_SIGNER_PRIVATE_KEY → Ethereum signed message format (EIP-191)
Returns: { signature, trustedSigner } — your permission slip for the smart contract
🔐 The smart contract only accepts scores signed by this trusted signer — no fake scores allowed
▾
7
⛓️Submit Score On-Chain (Transaction)
With the server's signature in hand, the app asks your wallet to send a transaction to the QuizScores smart contract. This is the only step that costs gas.
submitScore() Smart contract Gas fee 1h cooldown
Your wallet opens: "Confirm transaction?" with gas estimate
The QuizScores contract checks:
  • Is the cooldown (1 hour) over?
  • Did total == maxTotal (5)?
  • Is the signature from the trustedSigner? ✅
  • Is the nonce correct (prevents replay)?
Score is recorded → contract emits ScoreSubmitted event
Your totalPoints increases → totalGames increases
App polls the block explorer to confirm the transaction landed
App also calls /api/advance-progress to update the Redis wallet tracker
🎉 Done! Your score is permanently recorded on the blockchain!

🧩 The Big Picture

Quiz On Chain is a fully on-chain quiz game. Questions come from pre-written pools (hundreds per chain, stored as JSON files). Scores are verified by a server-side signer and then permanently recorded on the blockchain via a smart contract. You can earn points, climb the leaderboard, and claim a Master NFT Badge at 100 points.

🔑 Why the server signature?

Without the server's signature, anyone could call submitScore(5, 5) directly on the contract and lie about their score. The trusted signer (a private key only the server knows) cryptographically certifies: "This player really got this score — I verified it." The smart contract checks this signature before accepting.

🔑 How is cheating prevented?

3 layers: (1) Quiz answers are stored in a server-signed JWT — you never see the correct answers. (2) When you claim a score, the server recalculates it from your actual answers — if you lied, it refuses to sign. (3) The smart contract has a nonce and 1-hour cooldown — no replay attacks, no spam.

🔑 Leaderboard & NFT

All points are stored in the QuizScores contract. The leaderboard reads directly from-chain via public RPC. At 100 total points, you can mint "The What of Blockchain" NFT (ERC-721) via the QuizNFT contract. The NFT checks your points via a cross-contract call to the QuizScores contract.

📖 Key Terms

Question PoolA JSON file (data/quizzes-*.json) with hundreds of pre-written questions for a specific blockchain. No AI is used to generate questions.
quizToken (JWT)A signed token the server creates containing the correct answers. Sent to your browser but you can't read it — it's encrypted. Prevents cheating.
Trusted SignerThe server's private key. It signs your score so the smart contract knows it's legitimate. If there's no signature, the contract rejects the submission.
NonceA counter stored in the contract that increments every time you submit. Prevents the same signature from being used twice (replay attack).
CooldownA 1-hour waiting period enforced by the smart contract between your submissions. Prevents spamming the chain with many quiz attempts.
startIndexThe position in the question pool where your 5 questions started. Used to advance your progress for the next session and for replay protection in Redis.
