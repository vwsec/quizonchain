Key Strategy Comparison

Current sequential fallthrough vs proposed parallel ping — timing & token cost

CURRENT

Sequential Fallthrough

2

✅ Succeeds → done ~10–21s total
❌ 429 / timeout / error → try key2
3
Key2 → Groq LLM 30s timeout ~1500 tok
✅ Succeeds → done ~11–50s total
❌ Fail → try key3
4
Key3 → Groq LLM 30s timeout ~1500 tok
✅ Succeeds → done ~11–90s total
❌ All fail → fallback ~11–19s if fast 60s→504 if timeout
⚠ All-keys-timeout case: 3 × 30s = 90s needed, but maxDuration=60 kills the function → user gets a 504 Gateway Timeout, not fallback questions
PROPOSED

Parallel Ping → Generate

Ping all keys in parallel, pick a working one, then generate

1
Scrape docs — 6 URLs via Jina Reader in parallel ~8s
2
Ping all 3 keys — parallel, tiny payload (~20 tok each) 5s timeout ~75 tok total
2–3 keys healthy → pick first, generate once ~15s total
1 key healthy → generate on that key ~15s
0 keys healthy → instantly fallback ~13s
3
Generate on chosen key — full prompt, known-working API ~2–5s ~2000 tok (gen only)
✅ Always graceful: ping phase completes in ~5s regardless. If all keys fail, fallback reaches the user in ~13s instead of a 504.
